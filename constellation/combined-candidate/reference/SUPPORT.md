# Support scope and diagnostic record

Historical accepted spine recipe, supplied for reference configuration details. Run commands from the **combined candidate root**, not this reference subdirectory. Install packages using the main INSTALLATION.md and current PACKAGES.json; the historical nine-package table/explicit install command and 0.2.3→0.2.4 qualification examples below are not the combined install/upgrade path. Main DAY-TWO-RUNBOOK.md defines the supplied Workbench package-only upgrade/rollback. Historical whole-spine predecessor bytes remain separate private recovery custody, excluded from this public download. No historical qualification record is rewritten or required reading.
This prework supports one source-free Ubuntu 22.04 amd64 spine with the exact manifest packages, a filesystem-capacity observation profile, Nightshift observation recurrence, local attention and one separately enrolled canary start. Exact package/lifecycle/canary scope is recorded in QUALIFICATION-SUMMARY.json. Workbench/spine integration is accepted; formal human operability is prepared, not run, and BC1 remains unpublished. This is not a general fleet or service-management support envelope.

## Known limits

- Native version reporting is uneven: the LA CLI can report `0.0.0`/`unknown`, and Nightshift has no embedded source SHA. Exact package and installed-executable hashes in PACKAGES.json/EXECUTABLES.json identify this generation; do not substitute a short version string for those identities.

- Observation enrollment and effect enrollment are separate. Installation creates no executable grant. Default deterministic v1 needs no model/provider credential; optional v2 requires a separate owner decision and enrolled inference book/disclosure envelope.
- The remediation effect is a start of one pinned inactive/failed `attention-canary.service`, not restart of an active-but-unhealthy application. Completion needs a fresh post-settlement active observation and is narrower than durable application recovery.
- Same-root custody is a declared deployment premise. The consumer/issuer/AG/Docket/executor owner can replace local material. Exact pinning and reviewed source bound ordinary execution; they do not constrain the root owner or establish an isolated trust domain.
- Expired/exhausted/revoked standing can leave spent unresolved AG authority requiring owner reconciliation; no automatic broad archive/reset is supported. A torn grant-use entry refuses further derivation. Repair requires exact custody/use reconciliation and a new bounded grant/new journal with at most the justified remaining uses, preserving the old journal.
- Filesystem-capacity Nightshift support is unknown by construction. A successful cycle does not turn it CURRENT. The site adapter reads pinned internal NQ tables and is deployment glue, not a stable public query API.
- Cross-build active store continuity is unqualified. The documented upgrade path retains the previous generation and reconstructs current admission/qualification. Reinstallation can change helper inode identity; rollback is not a pure file restore.
- AG/NQ/LA logical inspections may touch locks, caches or database sidecars. Docket's exact governed custody inspector opens read-only. Do not assume an arbitrary copied book or a generic SQL query has the same owner semantics.
- A process alive, timer enabled, HTTP request successful or dashboard rendered establishes limited liveness only. Currentness, known effect outcome and fresh recovery must be inspected separately.
- Qualification retention defaults are not a long-running production retention plan. Purging packages has component-specific state semantics: notably NQ and LA preserve books, whereas attention's purge can remove its state. Preserve required evidence before any removal.
- New Workbench boot/HTTP reader interfaces and packaged provider-worker capabilities require their own accepted installation closure. Source presence or an old artifact is insufficient.

## What to include in a support report

Provide the exact combined/prework identity, package list/version/architecture, executable hash comparison and native build metadata. Include the time range and clock/currentness facts, the affected admitted watcher/canary and policy/profile generation, expected versus observed structured result, and the first refusal/error.

For observation/attention, include bounded redacted status/report fields, input statuses, preflight result, Nightshift recurrence result and notification custody/delivery disposition. For remediation, include exact occurrence/issuance/attempt/settlement identifiers, AG status/replay/refusals, Docket governed-loop inspection and fresh postcondition outcome. For optional v2, include the relevant LA milestone/reservation reconciliation verdict and typed accounting totals; provider charge/reporting questions remain distinct.

Use [OPERATIONS.md](OPERATIONS.md) to obtain existing records. Copy only bounded evidence needed to explain the issue. Preserve failed occurrence and rollback dependencies. Never initialize an absent store, resolve a grant use, run another consumer pass or silently repair the system merely to create a cleaner support report.

Exclude private issuer keys, SSH private material, provider credentials, route tokens/webhooks, environment files and unredacted command/configuration dumps. Do not publish real hostnames or private locators in a public report. Use a generic node label and maintain exact private custody separately. Raw artifact/history may contain more disclosure than a public status projection; review before sharing.

## Owner actions and recovery

Stop dependent effects when currentness, exact authority/custody or the runtime generation cannot be established. Keep the terminal outcome honestly failed, blocked or indeterminate. Follow the exact supported recovery/rollback document; no general shell fallback, grant regeneration, clock reset, schema edit or enlarged tolerance is implied by a refusal.

Provider enrollment/revocation, production route changes, new targets and live activation are separate owner actions. Qualification remains local-only unless the dedicated TEST PagerDuty route has explicit authority and verified distinct identity. Never redirect a qualification page to production.

A human operator needing undocumented architecture knowledge is a product/documentation defect. Record it through the prepared 12-task operability protocol; agent coaching or silent fixes cannot establish a human pass. Independent acceptance records the actual reviewed artifacts, evidence, scope and disposition separately from a preparation notice.
