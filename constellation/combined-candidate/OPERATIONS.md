# Operate the candidate

Enter through Workbench `/operator.html`; inspect its plan at `/plan.html`. The current native sources, raw provenance, gaps, attempts and refusal reasons are available alongside the interpretation. Workbench's `READ_OK` means the source binding/schema read succeeded. It does not mean every unit, host, dependency or application is healthy.

`current` supports the named native proposition within its enrolled identity and time boundary. `contradictory` describes evidence contradicting that proposition. `stale`, `absent`, `unsupported`, `refused` and unavailable reads remain explicit; browser refresh does not collect or refresh evidence. Newest unsupported evidence cannot be replaced by an older passing row. Boot identity, observation time, evaluation time and presentation time are distinct. Diagnosis and diagnostic-depth selection grant no effects.

The installed Workbench pages are **read-only**. Governed recovery uses the separate authenticated native API through the documented CLI escape. It selects fixed enrolled plans and never accepts a caller command or new target. On the admitted local exercise, after an owner-controlled unit stop and current native inactive/failed evidence:

```sh
sudo python3 scripts/native-action.py prepare --prestate inactive --assessment 'Current native evidence shows the enrolled unit inactive; cause is not established.'
sudo python3 scripts/native-action.py init
sudo python3 scripts/native-action.py record-proposal
sudo python3 scripts/native-action.py require-standing
sudo python3 scripts/native-action.py decide
sudo python3 scripts/native-action.py authorize
sudo python3 scripts/native-action.py dispatch
sudo python3 scripts/native-action.py poll
```

Inspect every native result. A successful HTTP response is not completion. Never repeat an uncertain dispatch. `OBSERVATION_CHANGED` during preparation means acquire fresh context for a new non-authorizing preparation only if no attempt was created. Later refusals preserve the existing attempt; inspect `/api/attempt` and reconcile before any recovery operation. No automatic retry is supplied by these helpers.

After exact settlement, explicitly continue into an authority-empty successor and independently wait for fresh current active-unit evidence, including the native postcondition/dwell requirement:

```sh
sudo python3 scripts/native-action.py continue
sudo python3 scripts/native-action.py complete
```

`CURRENT_POSTCONDITION_REQUIRED` means wait for actual fresh evidence; do not relax time bounds or force success. Inspect the original and successor occurrences, native AG result and Docket custody. The package includes `ag-loopctl` inspection and Docket's installed enrollment/inspection manual as CLI escape hatches. Do not invoke standing-grant resolvers as read-only probes.

Attention distinguishes informational, attention and page classes. PagerDuty page intent is separate from submission/delivery and from effect authority. Missing input does not establish recovery. The local exercise configures no external notification destination. Reference observation/evaluator/notification/status and optional metrics/Grafana procedures remain in the bundled reference operation and observability manuals; this Workbench cohort does not claim to unify those surfaces into one universal health score.

Deterministic remediation v1 remains the reference default. Qualified optional v2 uses Linear Accountant to reserve, fence, settle and reconcile inference expenditure; AG/Docket retain authority/custody and fresh observation determines recovery. The Workbench reveal did not exercise LA; separate remediation-v2 qualification did. Installation, diagnostic depth, model narration and package presence activate none of that optional authority.

Build inspection: `nq --build-info`, component `--build-info` where documented, `/usr/share/constellation-workbench/build.json`, `dpkg-query`, PACKAGES.json and RUNTIME-IDENTITIES.json. ## Optional inference accounting

Admitted model-backed workflows can disclose the actual LA envelope before
inference and native usage/settlement afterward. Workbench's optional read-only
accounting pane displays selected owner-exported LA assertions. It does not
estimate provider cost or administer budgets. A closed/revoked token's numeric
remaining capacity is retired, not available spending. Unknown actual cost
stays unknown; budget exhaustion offers no continuation action. Accounting is
explicitly recorded and distinct from current evidence/effect authority.

## Understand monitoring notices

A condition ID is an exact correlation key, not an explanation. `unknown` or `indeterminate` means the available evidence cannot justify a conclusion; `stale` means it is outside the qualified age/boot boundary. None means healthy. A current `clear` applies only to the named proposition. A notification `resolved` closes that condition lifecycle: restored monitoring does not by itself prove the observed service was repaired. Inspect the evidence and scope, then the documented collector/runbook before acting. A page may require prompt human investigation because an obligation cannot be evaluated. Exact IDs remain useful when correlating native records and delivery outcomes.
