Public source

The confirmed family names are shown here, but the remote repositories have not yet been renamed. These links deliberately use their current addresses.

  • Constellation AG — authorization, observation, standing, one-use decisions, and the read-only Phosphor inspector: current ag_ng repository.
  • Constellation Docket — custody and settlement for bounded execution attempts: current docket repository.
  • Constellation Nightshift — currentness, lineage, and attention over time: current nightshift repository.
  • Maude — plan authoring, checking, comparison, and locking: current maude repository.

Constellation NQ is the confirmed name for the successor diagnostic engine, but that successor does not yet have a public source path. The public nq repository is the deprecated predecessor, not the successor under a new label.

What you can do safely today

  1. Read each repository's current README and public guide. Check the stated maturity, supported surface, and deployment assumptions for the component you need.
  2. For authoring, begin with Maude's Plan Core documentation and source-only tests. Drafting, checking, comparing, and locking a plan do not perform the planned work.
  3. For inspection, follow Constellation AG's operator UI documentation. Phosphor is read-only: it can show joined records but cannot accept a plan, grant authority, rerun work, or settle an occurrence.
  4. Build or test only the component whose documented prerequisites you have. Do not infer compatibility between repository heads or between classic and successor components.

Synthetic-cache tutorial status

The tutorial kit describes a credential-free, disposable four-container local HTTP/cache workload. “Credential-free” means no model-provider credential is required; a clean machine may still need network access to fetch source dependencies and a pinned container image.

Its Maude plan generators and selected source-level checks are verified. The documentation campaign has not completed the connected runtime run. That check requires exact compatible source revisions and built executables, access to an explicitly selected local Docker daemon, Compose, the pinned image, and a fresh disposable workspace. The runner/source-path mismatch has been repaired locally; publication and the end-to-end runtime check are still pending.

Keep the results straight: a passing source test supports the source behavior it checked. Successful artifact generation supports the generated structure. Neither result establishes that containers ran, that the connected offices agreed, that teardown completed, or that a different host is qualified.

Before any effectful run

Use the repository's read-only preflight first. Confirm exact revisions, executable identities, local runtime access, storage availability, and an exclusive disposable workspace. Review what the run may change and who may authorize it. Afterward, inspect the attempt outcome, current observations, attention items, and settlement separately. If the outcome is uncertain, reconcile the existing attempt before considering any new action.
