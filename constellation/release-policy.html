Integration releases identify tested combinations

A suite version describes named integration profiles, not a simultaneous release of every Constellation component.

The first target is 0.1.0-alpha.1. Until qualification and publication finish, the candidate profile list is not an installable release manifest. Component versions, existing tags and release lines remain independent.

What a released manifest fixes

Each immutable snapshot names its profiles, exact public component commits, runtime/toolchain requirements, relevant configuration and schema versions, matching examples, documentation and qualification evidence. Artifact or dependency digests are included where used. The manifest schema version is separate from the suite version. No credentials or private installation prerequisites belong in a released profile.

The evolving family inventory answers what exists. A released manifest answers which exact combination was exercised. Family membership alone does not put a component in a tested release.

Release stages

  • Alpha: a tested external integration path with explicit limitations; interfaces may still change. Support is best effort, without a guaranteed response time.
  • Beta: evidence that the advertised external path is sufficiently stable and exercised, including relevant failures and recovery.
  • Stable: an explicit support and compatibility commitment in addition to qualification evidence.

Changing a snapshot

Changed runtime pins or integration contracts require a new prerelease. Never move an existing release tag, replace published manifest contents, or regenerate a released manifest from current repository heads. If a proposed version already exists, select the next unused prerelease. Identify documentation-only corrections separately when tested runtime pins and contracts are unchanged; retain the original snapshot and link the correction.

Evidence and limits

A release must reproduce its advertised external example from public sources in a clean environment and verify relevant refusal, uncertainty and recovery. Synthetic inputs are labeled, and cannot replace the capability the profile claims to demonstrate. Recorded results do not establish present system state; settlement does not establish success or permit continuation.

General ECAD/design-flow readiness and unsupported federation are outside the first release. Qualifying one profile does not complete other tutorials or imply family-wide maturity. Start with the composition guide; use the support guide when a documented path fails.
