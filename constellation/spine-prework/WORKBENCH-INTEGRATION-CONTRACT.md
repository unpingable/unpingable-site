This is the authoritative integration contract for the selected candidate, not a release, installed-runtime acceptance, Workbench implementation order or production activation. Exact package/executable manifests and fresh target receipts must be frozen before the candidate is accepted. Component source qualification does not grant Workbench actions.

The [inclusion matrix](INCLUSION-MATRIX.md) defines what enters this target. The [branch reconciliation record](BRANCH-RECONCILIATION.md) explains its source selection and held dependencies. A required missing package, field, tool or qualification result remains a gap; it is never substituted with a historical receipt.

## Transport, logical reads and filesystem effects

A logical read supplies an owner assertion without requesting a work transition or spending inference/grant authority. That does not imply an OS operation that cannot write locks, caches or SQLite sidecars. These axes stay separate in documentation, admission and deployment permissions. No inspection command may be chosen merely because its name contains `status`, `inspect`, `reconcile` or `dry-run`.

The baseline transports are fixed installed CLI argv and local retained files. Pulse additionally provides a bounded canonical exchange over an already connected local Unix stream; it creates no listener, daemon, pathname, store or server loop. Workbench's HTTP adapter is its own installed composition, not a native Monitor/LA/Docket REST API. Browser clients select neither source executable, arbitrary argv, environment nor filesystem paths. Workbench's existing trusted command is limited to 1..5000 ms and at most 2 MiB; the selected source owner still owns its query bounds, identity and semantics. Length/duration limits, canonical decoding, exact endpoint/peer binding and permitted filesystem writes must be recorded by the actual embedding. Hashes detect correspondence, not endpoint authentication.

## Status, raw artifacts and provenance

Workbench preserves the native owner object and cites exact fields. Metadata already represented by the retained catalog, live manifest/owner objects, package manifests or native records must remain visible under progressive disclosure: owner/contract/schema version, logical subject/cohort and implementation generation, source revision/build/package/feature identity, raw byte digest, native record identity, observation/acquisition/evaluation/owner-read/capture times with their clock/boot lineage, currentness/judgment and reason, authority/custody/attempt/settlement identities, and acceptance/evidence pointers. A missing field is an explicit gap; it is not synthesized from Git author, process exit, page time or a neighboring record. This list is an integration requirement mapped onto existing records, not a new universal wire schema.

The status artifact contains `schema`, `artifact_id`, `projection_id`, `projection_generation`, `policy_digest`, `generated_at_unix_ms`, `fresh_until_unix_ms`, `admitted_clock_uncertainty_ms`, optional observation window, `aggregate_state`, components, optional operator basis digest and explicit nonauthorization fields. Components contain id, optional display name, state, mode and disclosed reason/detail. `constellation.status_current_pointer.v1` binds the immutable object identity. Canonical artifact validation and SHA correspondence do not certify source truth or fresh support.

Only `observed` and `derived_admitted` facts can establish projection state. Asserted, historical and qualification-lifecycle facts cannot. `SourceFactV1` is an in-process adapter product and deliberately has no deserialization API; serialized digest inputs must not be adopted as an importable owner-fact wire. Native leaf adapters retain their own meanings. Owner detail is display-only and operator-only; it changes neither basis nor authority. A reduced public audience is an information-disclosure setting, not a qualified public capability-availability service. Disclosure reduction happens before rendering/publication; operator raw artifacts are not automatically public.

## Owner-specific temporal meaning

Never flatten these separate vocabularies into a shared health/currentness enum:

| Owner | Native values | Meaning to preserve |
| --- | --- | --- |
| Pulse judgment | `CURRENT`, `DEGRADED`, `SUSPECT`, `UNKNOWN`, `CONTRADICTED` | Only CURRENT supports that consumer's exact present reliance; it is not healthy or permission. |
| Pulse live response | `supported_current`, `expired`, `unsupported`, `indeterminate` | Exact installed support, expiry, definite selector/source non-support, or unavailable temporal custody. Positive remaining duration is local to receiver lineage and must lose full caller elapsed time. |
| NQ detector | Native `present`, `explicitly_absent`, `cannot_evaluate` and other source-defined outcomes | Profile/testimony/policy-specific condition result. `explicitly_absent` can support an enrolled HTTP postcondition while `present` names its violation; no universal up/down mapping. |
| Monitor systemd-v2 AG resolution | `current`, `stale`, `contradictory`, `absent`, `unsupported`, `refused` | Exact active/not-active proposition on newest enrolled NQ evaluation, not application health. `currentness` field is a witness digest; it is not another enum or freshness certificate. |
| Projection state | `healthy`, `degraded`, `partial_outage`, `major_outage`, `unknown`; mode `normal`/`maintenance` | Projection-local policy/audience conclusion only. Source freshness axes are `fresh`, `stale`, `missing`, `contradictory`; they do not replace native outcome vocabulary. |
| Attention observation | `present`, `clear`, `unknown`, explicit removal semantics | Bounded condition/persistence lifecycle. Missing or stale input cannot establish recovery; explicit removal is operator disposition, not an observed recovery. |
| Workbench inspection | Native owner currentness/judgment quoted; inspection gaps/refusal separately labelled | Byte/schema/source failure describes inspection failure, not a component outage or completed/refused work. |

Pulse uses receiver-owned monotonic duration. Caller timing anchor starts before request transmission, is consumed once, and subtracts the entire query/decoding/admission delay plus later waiting. Zero remaining support is unusable. Retained response bytes, request nonce repetition, browser refresh and a new wall-clock timestamp do not refresh it. Restart/receiver-epoch/clock-lineage changes refuse old support. Never compare monotonic ticks across processes or turn them into wall-clock deadlines.

Projection `fresh_until_unix_ms` is a conservative presentation deadline on the admitted caller timeline. At or after it, the renderer hides retained component conclusions and shows unavailable; it is not a persistent source freshness claim. The exact observation window and clock uncertainty remain visible. A cache cannot extend the deadline.

NQ source testimony reliance and consumer evaluation/artifact maximum age are independent. A later evaluation of old evidence must not silently extend the source proposition. In the accepted #71 occurrence, the prior good NQ evaluation used a 90-second evaluation bound, while testimony aged 60.039 seconds violated its independent 60-second reliance. The newest `cannot_evaluate` was correctly Unsupported. The fix changed collection cadence 60→30 seconds and rotated its supported observation binding; no tolerance or AG/resolver law widened. Exact authorize stdout was not retained, so the diagnosis is source/timeline reconstruction with that explicit evidence limit. Workbench must preserve newest unsupported evidence and the reason; it cannot substitute an older good row, retry into support or relabel the read time as observation time.

Workbench's current live validation pins exact cohort host identity, component revision/build hashes, subject/profile identity and observation boot to host boot; native raw records remain separate. `asserted_at`, `read_at`, source observation time and page capture are distinct. Settings/manifest `diagnostic.level` and `required_levels` are declared selection requirements, not grants.

## Attention, paging, remediation and accounting projection

Attention uses `constellation.attention_report.v1`, registry `constellation.attention_registry.v4`, and `constellation.attention_state.v1`. Preserve report evaluation time/policy digest/input dispositions; each condition's id/rule/observation/note/reference, first-seen/unknown-since/persisted/persistence bounds, active/transition, response policy, remediation-window end and page-deferred state. Preserve intent route role/stable event and transition identity/schema/notification id/native outcome and unresolved/dropped delivery evidence. Do not infer ongoing presence or clearance from `active` alone, nor delivery from an intent being constructed.

NQ owns notification custody, route selection, destination credentials and delivery. Native response classes are closed `page`, `attention`, `informational`; PagerDuty uses page routes and local/Slack delivery retain their own semantics. The UI distinguishes prepared/retained/submitted/refused/delivered outcomes by native records; an accepted TEST delivery is neither effect authority nor recovery. A held page/remediation window is an evaluator lifecycle record; reading it grants no attempt and does not authorize suppressing or sending a page. Qualification escalation uses the dedicated TEST route only. Never invoke a live submit/resubmit/deliver operation to verify an inspection card.

Remediation state `constellation.remediation-consumer.state/v1` and journal `constellation.remediation-consumer.journal/v1` are accountable consumer records. Quote exact condition episode, campaign/occurrence, subject/scope/plan/work, phase, dispatch fence, issuance/attempt/settlement, postcondition/fresh observation and outcome. Consumer `awaiting_postcondition`, Docket settled effect and AG's native lifecycle remain distinct; none becomes a universal successful state. Missing or stale postcondition remains indeterminate/escalated as the owner records it. Model response may be displayed only as bounded narration/closed decision with source label; it cannot select UI action targets, grant, plan, retries or effects.

Default remediation stays deterministic v1. Optional v2 requires its exact LA enrollment/budget, disclosure envelope, provider/model request identity, credential custody and explicit production activation owner direction. Source qualification alone activates nothing. The synthetic provider fixture and `qualification-loopback` artifact remain outside ordinary installed runtime; no real provider key enters that branch. Credentials, private key bytes and authorization headers never enter the Workbench catalog, raw export or report. Presence/custody path/owner/mode and public fingerprint may be recorded when needed; secret content and provider-key digest must not be retrieved for a card.

LA inspection retains admission/milestone/reservation/invocation/receipt and typed outcome, enrollment ceilings, granted/consumed/retired/available accounting, actual-known/unknown and assumed-ceiling measures, reconciliation findings and provider metadata. Units stay explicit: integer microUSD accounting differs from decimal provider-reported USD and invoice truth. Missing provider usage is conservatively charged, not measured actual usage. Inspect every relevant milestone/partition, including intentional negative controls; a main PASS does not hide a separate expected breach FAIL. Carried owner remainder is not summed as another original deposit. The cross-store milestone cap is owner allocation arithmetic, not LA's global enforcement. A model invocation cannot be recreated or resent merely to make inspection complete; uncertain transmission/recovery remains source-owned and may be accounted at ceiling.

## Metrics and build identity

Native library measures include typed `ExperimentalMetricsV1`, sparse `MetricsSnapshot`, `RuntimeMetricsV1` and `ReactorMetricsV1`, plus owner-specific report counters. They are component data surfaces, not an automatically running exporter or endpoint. Display raw measure name/unit/source/window/lineage and missing fields. Coverage, expiry, duplicate/drop and latency measurements do not create health, causation or operational authority.

The [Beta Observability MVP](observability/README.md) already provides a site-owned `constellation-textfile-exporter.py` and timer. It reads selected retained/status/systemd/SQLite surfaces, writes a Prometheus-format textfile atomically, and can feed node_exporter's textfile collector, VictoriaMetrics, vmalert and Grafana. This is an existing subset adapter and an optional deployment composition; fresh candidate operation and dashboard acceptance remain to be recorded. Missing input omits its families and emits an input-validity metric. Bounded labels exclude evidence/artifact identities, subjects, paths and free-text reasons. Its operational alerts indicate machinery trouble; they neither replace Attention's conditions nor page through PagerDuty. Do not describe this adapter as nonexistent or as a universal native exporter. No native cross-owner `/metrics` or OTLP interface is established by the frozen component target.

Package version alone is insufficient build identity. The frozen BC1 manifest must name exact source/export/lock/toolchain/builder image/features, full executable and package hashes, installed ABI/systemd floor, source epoch and qualified result identities. Attention emits `constellation.attention_build_info.v1` with name/version/source commit/registry/minimum NQ/Rust compiler. New public replay uses its actual new source commit, never impersonates the private qualified binary. AG tools/effectd use the selected systemd-dbus package contract; Docket packages all three custody/standing binaries and the needed installed enrollment manual; LA uses its inference feature/package. NQ's six build-info identities/profile catalog and Nightshift's external ELF/source manifest remain their own checks. Qualification-enabled fixture features, debug/dev hooks and provider-worker tools must not silently enter ordinary packages.

## Scope limits and formalization consideration

This contract relies on trusted fixed installed commands, native store/issuer/custodian correctness, declared clock/boot assumptions and provider reporting/compliance where applicable. A digest or schema match does not authenticate truth; same-root custody does not constrain its root owner. OS-level no-write behavior is asserted only where source actually opens read-only; logical inspection is the broader stated property. The product claims are confined to each component's exact accepted scope and records.

Proposition: source-labelled inspection composes observation/currentness, attention, authority, execution/custody, postconditions and accounting without refreshing evidence, advancing work, spending authority or broadening operational permissions. Existing source guards, separate native enums, exact artifact identity and bounded deterministic/integration evidence are sufficient to specify this no-runtime-change document. No new formal model or API is introduced. A later small transition model could cover inspection/recovery and time cuts, but only under a separately admitted owner task. Counterexamples/unknowns include untrusted installed commands, invented/relabelled facts, absent source fields, cross-host clock interpretation, omitted package tools and the new Workbench merge drift. The spine integration owner owns the composition decision and independent acceptance; this lane supplies the exact contract/evidence pointers for review.
