Propositions under qualification:

- Packages bind exact source/build identities and install inert tools/units,
  preserving the accepted authority and custody boundary.
- Reference observation enrollment mints no AG/Docket grant. Separate
  owner action enrollment pins one attention-canary.service subject,
  current machine, inactive/failed start plans, active postcondition,
  finite grant, revocation marker and use journal.
- The reference installation predicate refuses wrong identity/profile,
  unknown state, stale or excessive future evidence even under optimized
  Python execution. Independent AG/NQ currentness remains authoritative.
- A schema13 internal read adapter refuses other schema versions; it does
  not become a general observation API.
- Upgrade/rollback follows archive and explicit fresh-generation admission
  and qualification; a version change alone proves neither invalidity nor
  continuity of an existing store.

Practical tests, exact source/binary correspondence, independent review and
focused real Jammy installation/lifecycle/effect checks are sufficient for
this composition change. No new concurrent algorithm or durable authority
mechanism is introduced, so a new formal model would not justify additional
product claims here. The final acceptance record binds actual package and
result identities; a prepared protocol or completion notice is not acceptance.

Limits and counterexamples: same-root mutation is outside the stated boundary;
manual owner editing changes enrollment; a package hash alone proves no
runtime health; historical receipts cannot report unobserved current success;
service existence cannot substitute for progress; unchanged schema cannot
qualify cross-build store continuity. Refusal and indeterminate remain valid
results. Workbench presentation/integration and the combined human journey
remain separately gated. No formal proof of the whole deployment is claimed.
