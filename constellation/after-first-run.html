After the first run

This is lifecycle guidance for the public 0.1.0-alpha.1 source routes. It is not a release or compatibility promise for a connected runtime.

Current boundary: the credential-free Maude walkthrough creates a local Plan Core fixture. Its authoring, checking, comparison, and locking steps do not execute planned work. The candidate read-only Maude external-caller profile is not qualified or released.

Inspect before you restart

Keep the exact public revision, the local store location, and the selected draft and revision identifiers together. For a Plan Core store, use the documented maude-plan inspect, check, diff, and lock commands against an explicitly selected store and draft. A check or lock is evidence about exact plan bytes; neither is permission to run work.

If the local design server was interrupted, restart it against the same retained stores as described in Maude's design guide. Do not rerun the fixture generator over that path. Inspect the selected revision and proposal disposition first. If browser state and stored records cannot be reconciled, preserve the corpus and use a new path for a separate exercise.

Configuration, credentials, and ownership

The deterministic fixture route needs no model-provider credential. The optional enrolled-provider route has a separate caller-owned credential file and budget; creating or starting that route does not authorize a provider call. Keep credentials out of commands copied into notes, shell history shared with others, logs, and issue reports.

Assign one local owner for each retained store, relevant local log, and backup copy. Record the exact source revision, Python environment, selected profile (if any), store paths, and relevant plan/check/lock/proposal identifiers with that owner. Do not treat a source checkout, a browser tab, or a generated fixture as a shared service.

Stop, restart, and uncertain attempts

Stop the foreground walkthrough server with its documented foreground control, then retain the stores if they contain records you may need to inspect. Restarting a UI does not establish that a governed attempt stopped or settled. Where a connected governed attempt has an uncertain outcome, reconcile that existing attempt and its retained records before considering another action; do not repeat the work merely because a client was interrupted.

Back up and restore deliberately

Quiesce the local writer before copying a retained SQLite store. Keep the backup with its exact source revision, environment details, selected profile configuration, and record identifiers so that a later reader can identify what it contains. Test a restore only in a separate disposable copy; never use a speculative restore as evidence that the original store is current.

The public alpha does not publish a migration, compatibility, or rollback procedure for the candidate external-caller profile. Do not upgrade or restore that profile across unknown versions. Before any future published compatibility path, preserve the old state and source coordinates, read that path's release notes, and use only its stated procedure.

Retain evidence; clean up disposable exercises

A fresh walkthrough corpus is disposable only after you decide that its drafts, checks, proposal dispositions, and logs have no replay or diagnosis value. Retain records for an interrupted or uncertain exercise until their state is understood. Remove only the local disposable directory you selected, never an unreviewed shared store or another operator's workspace.

For symptoms and a minimal support report, use the troubleshooting guide. For initial setup, return to Start with the source.
